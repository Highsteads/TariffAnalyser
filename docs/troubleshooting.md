# When something goes wrong

Each section starts with what you see, then what it means and what to do.

## "Timeseries DB not found. Check SigenEnergyManager is running v4.6+."

The plugin cannot find SigenEnergyManager's energy database. The Tariff Comparison dialog shows this under the period, and the Energy Summary and the actions put a warning in the Event Log instead.

- Check SigenEnergyManager is installed, enabled and at version 4.6 or later.
- If you have typed a path into **Timeseries DB path** in the plugin's settings, clear it so the plugin finds the database by itself.
- Choose **Plugins → Tariff Analyser → Show Plugin Info** and check the path it gives for the energy database.

## "No data in the timeseries DB yet."

The database is there but has nothing in it. SigenEnergyManager writes the first line after its first full half-hour, so wait half an hour and try again.

## "No data for" two dates

SigenEnergyManager has no record for the period you chose. Choose a longer period, or check SigenEnergyManager was running during those days.

## Agile shows "insufficient price data to rank"

The plugin has Agile prices for less than half the period.

- If the report came from the **Generate Tariff Comparison Report** action, put **Update Octopus Agile Price Data** before it, as the [Actions](actions.md) page shows.
- Choose **Plugins → Tariff Analyser → Test Octopus API Connection**. If it warns that no tariff was found, check **Octopus region (for Agile prices)** in the settings, using the table on the [Settings](settings.md) page.
- Check the Mac can reach the internet.

## The report says the tariffs were compared over less than the whole period

At least one tariff has gaps in its prices, so every tariff was priced over the half-hours they all have prices for. The ranking is still like for like, but the pound figures are for that share of the period, not all of it. The **Coverage** column shows which tariff has the gaps.

## An Energy Summary card says "No data available"

SigenEnergyManager has no record for that period — this year, say, if you started it recently.

## The log warns "Octopus API key not configured"

The nightly collection needs an Octopus API key and found none. The reports are not affected. If you want the nightly collection, fill in **Octopus API key** in the settings, or add it to `IndigoSecrets.py` as the [Settings](settings.md) page describes and restart the plugin.

## You filled in IndigoSecrets.py, but Show Plugin Info says the details came from PluginConfig, or were not found

The plugin only uses the file if it has all seven Octopus lines, and it reads the file when it starts.

- Check the file has every line listed on the [Settings](settings.md) page, with `""` for any you do not have.
- Restart the plugin.

## The log warns it "Could not get the Indigo install folder from the server"

Indigo's server was slow to answer when the plugin asked where its folders are, usually because several plugins were starting at once. The plugin keeps trying each time it needs the folder and logs a line when it gets an answer. Until then it cannot find the energy database or the Agile prices, so wait a minute and try the report again.

## A scheduled report did not open

A report made by the **Generate Tariff Comparison Report** action only opens if **Open report in LibreOffice when generated by a schedule/action** is ticked in the settings. Either way it is saved in the output folder, and the Event Log says where.

## Still stuck?

Choose **Plugins → Tariff Analyser → Show Plugin Info**, copy the lines it writes to the Event Log, and post them on the [Indigo forum](https://forums.indigodomo.com) with a description of what you see. You can also [raise an issue on GitHub](https://github.com/Highsteads/TariffAnalyser/issues).
